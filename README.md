# 场馆档期安全联锁

面向同时承接职业联赛、青少年比赛、群众活动与临时国际赛事的综合体育中心，把主馆、训练区、设备、人员资质和监管批文纳入统一的档期联锁服务。

## 核心规则

- **布撤场窗口**：任何预留的占用区间为 `[开场-布场时长, 散场+撤场时长)`，窗口重叠即视为场地冲突。
- **安全容量**：`场地容量 × 监管保障级别系数`（1 级 100%、2 级 80%、3 级 50%），超售即硬冲突；安保人数按观众数 1:250 自动推导并占用具备有效资质的人员。
- **三级状态**：`暂定(tentative) → 签约(contracted) → 进场(load-in)`，三种状态都真实占用资源；所有写操作串行执行，检查与落库之间不会插入其他变更，杜绝两笔并发操作重复占用同一档期。
- **硬冲突与软缺口**：场地占用、容量超售、缺少监管批文属于硬冲突（拒绝并留痕）；设备/人员不足属于软缺口，预留可先暂定、承办方可见，签约前必须解决。
- **变更不静默**：设备故障、证照吊销、监管提级只做影响分析——标出实际受影响的场次并给出替代方案（替换设备/减量/降员/换馆/改期/补办批文），生成待确认通知；系统绝不自动改动任何预留。已售票活动调整时间或场地，必须由值班经理以 `confirmTicketedMove` 显式确认。
- **分权视图**：承办方只能看到自己场次的资源缺口与通知（冲突详情中对方活动信息被屏蔽）；值班经理可查看台账、日历、审计日志并回放已结束场次。
- **可回放**：全部变更事件溯源留痕。值班经理可回放某日为何拒绝冲突申请、哪次变更通知已被确认，并从已结束的场次复原当时有效的场地状态、人员排班和放行依据。

## 运行

```bash
npm run check        # 核对服务身份与状态回放
npm test             # 接口契约与领域规则测试
node service.js          # 启动（默认 127.0.0.1:8000）
node service.js --seed   # 启动并载入演示数据
```

角色通过请求头声明：`x-role: manager`（默认，值班经理）或 `x-role: organizer` + `x-organizer-id`（承办方）。生产部署时应由前置网关替换为真实鉴权。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| POST | `/spaces` `/equipment` `/staff` `/permits` | 登记场地/设备/人员资质/监管批文（经理） |
| GET | `/resources` | 资源台账（经理） |
| POST | `/bookings` | 创建暂定预留，返回窗口、容量、排班与缺口 |
| GET | `/bookings` `/bookings/:id` | 列表/详情（承办方仅见自己的） |
| GET | `/bookings/:id/gaps` | 实时重算资源缺口（经理另见冲突明细） |
| POST | `/bookings/:id/confirm` | 签约：硬冲突与缺口必须全部解决 |
| POST | `/bookings/:id/load-in` | 进场（经理）：记录放行依据 |
| POST | `/bookings/:id/complete` `/cancel` | 完结（经理）/取消 |
| POST | `/bookings/:id/adjust` | 调整并重估；已售票场次改期/换馆需经理显式确认 |
| POST | `/incidents/equipment-fault` | 登记设备故障，返回受影响场次与替代方案通知 |
| POST | `/incidents/equipment-fault/:id/resolve` | 故障恢复 |
| POST | `/permits/:id/revoke` | 吊销批文并做影响分析 |
| POST | `/regulations` | 调整保障级别并做影响分析 |
| GET | `/notices` | 变更通知（承办方仅见自己场次的） |
| POST | `/notices/:id/ack` | 负责人确认变更通知 |
| GET | `/audit?day=&action=&bookingId=` | 审计回放：拒绝原因、确认记录等（经理） |
| GET | `/calendar?day=YYYY-MM-DD` | 当日占用日历（经理） |
| GET | `/bookings/:id/replay` | 复原已结束场次当时有效的场地状态、排班与放行依据（经理） |

## 代码结构

- `lib/domain.js` — 纯函数领域核心：窗口、容量、冲突、缺口、影响分析、替代档期搜索
- `lib/store.js` — 事件溯源存储：变更日志 + 按时刻回放复原
- `lib/api.js` — HTTP 路由、角色分权、写操作串行化
- `lib/seed.js` — 演示数据
- `service.js` — 服务入口与自检
